# Единые аккаунты MILA и Agentic OS

## Что является источником истины

Учетные записи создаются и хранятся только на сервере Agentic OS. Веб-панель и
мобильное приложение используют одинаковые email, пароль, `user_id` и роль.
Пароли хранятся как необратимые хеши и не передаются в MILA после входа.

## Вход с телефона

1. Приложение отправляет email и пароль в
   `POST /api/auth/mobile/login` или создает аккаунт через
   `POST /api/auth/mobile/register`.
2. Agentic OS возвращает подписанный мобильный access token. Он хранится в
   Android Keystore или iOS Keychain.
3. Приложение обменивает этот token через
   `POST /mila/v1/auth/agentic` на отдельную MILA voice session.
4. Основной token используется только с `/api/member/*`. Voice session
   используется только для Gemini Live и LiveKit.

Пользователь выполняет вход один раз. Разделение токенов происходит внутри
приложения и не показывается пользователю.

## Синхронизация

- `/api/member/tasks` хранит личные задачи пользователя.
- `/api/member/notes` хранит личные заметки пользователя.
- `/api/onboarding` формирует личный `SOUL.md`.
- Все данные изолируются сервером по `user_id`, а не по имени или email.
- Изменение роли или отключение аккаунта аннулирует ранее выданные мобильные
  токены через `sessionVersion`.

## Совместимость

Старый восьмизначный код подключения оставлен для уже установленных сборок и
административного обслуживания. Новые пользователи должны использовать обычную
форму регистрации или входа в мобильном приложении.

## Выход

При выходе приложение удаляет оба токена из защищенного хранилища и очищает
локальный признак авторизации. Серверные личные данные остаются в аккаунте и
снова появляются после следующего входа.
